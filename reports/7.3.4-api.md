## API
실행
```powershell
$env:YAMU_AI_MODEL_DIR = "models\hgb-poisson-20261102-fraud-large-recurring"
.\.venv\Scripts\python.exe -m uvicorn --factory forecast_ml.api:create_app --port 8001
```

`POST /forecast/living-cost`
```json
{ "asOf": "2026-11-02", "horizonDays": 7,
  "accounts": [ { "key": "a1", "dailySpending": [0, 0, 5000, "… 90개, 마지막이 asOf 당일"] } ] }
```
응답
```json
{ "modelVersion": "hgb-poisson-20261102-fraud-large-recurring", "horizonDays": 7,
  "predictions": [ { "key": "a1", "amount": 37562 } ] }
```
- `dailySpending`: asOf까지 90일의 일별 체크 생활 소비(원, 0 이상 정수, 하루 1조 원 이하). 원천 정제(정기·큰 일회성 지출 제외)는 BE가 한 뒤 넘긴다.
- `key`: BE가 정한 임의 구분값(1~64자, 요청 안에서 겹치면 안 됨). 사용자 ID·계좌번호는 받지 않는다.
- `amount`: 다음 horizonDays일(asOf 다음 날부터) 합계 예측, 원 단위 반올림, 0 이상.
- 계좌 1~20개.

오류
| 상황 | 응답 |
|---|---|
| 90일이 아님, 음수·상한 초과, key 겹침, 계좌 0개·21개 이상, 필드 누락, 날짜 형식 | 400 `INVALID_REQUEST` + `fieldErrors`(위치·이유만, 입력값은 되돌려 주지 않음) |
| 모델이 없는 horizonDays(7·14·30 밖) | 400 `INVALID_REQUEST` |
| 모델 폴더가 없거나 읽기 실패 | `/health` 503 `model_missing`, 예측 503 `MODEL_MISSING` |

`GET /health`: `{"status": "ok", "horizons": [7, 14, 30], "modelVersion": {...}}`

- 모델은 앱 시작(lifespan) 때 한 번 읽는다. import 시점에는 아무것도 읽지 않는다(`--factory`로 실행).
- 로그에는 horizon·계좌 수·처리 시간만 남기고 요청 본문은 남기지 않는다.
- 특징 계산은 학습 때와 같은 `forecast_ml.features.make_features`를 쓰고, 모델 설명의 특징 순서와 다르면 거절한다.

## 7.3.5로 넘기는 것
- 잔고예보 기간이 7·14·30일이 아닐 때: `until=NEXT_INCOME`이 연결되면 다음 월급일까지 임의의 일수가 된다. 모델은 7·14·30일만 있으므로 "가장 가까운 큰 모델의 하루 값 × 일수" 같은 규칙을 정해야 한다.
- 보수적 선의 하루 값: 합계 ÷ H를 날마다 같은 값으로 뺄지(지금 AVG_3M과 같은 방식) 정한다.
- 원천 계약을 일별로 바꾸는 것(BE 1·BE 2 합의), BE 호출 시간 제한·실패 시 AVG_3M(또는 TSB) 대체, 응답 `method` 구분.
- 팀 레포 `ai/`로 옮길 때 Python 3.12에서 다시 테스트, 모델 파일 배포 방법(7.3.6).
